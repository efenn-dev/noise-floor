# Stress test, 2026-10-13 (numbers only)

Machine: **Emmitt's PC, Godot 4.7, headless.** Script: `test/stress/stress_sim.gd`, run with `tools/stress.sh`.

Setup: `SimWorld` with `power.free = true`, 50 machines (25 smelters, 25 presses, each on a foundation in a 10 x 5 block just south of the town), topped up by hand every 10 s outside the timed step so all 50 craft the whole run, shamblers from `horde.spawn_town` on the main street, player far away (500 m) so nothing chases. `sim.step()` called directly, TICK = 1/20 s, starting at 19:00. **Shrunk:** a full game-day (28,800 ticks) would have taken about 113 s of wall time per run, over the 90 s budget, so every run is **4 game hours (4,800 ticks, crossing sunset)**.

Not in these numbers: zombie bodies, navmesh and physics. A sim-only run never moves zombies (their world bodies do), so the 200 stand where they spawned; the 20-zombie run hit `max_alive` (40) through six Director waves, which is why it ends with 40. With 200 alive the Director never sends a wave (its cap is 40).

**Reading.** A tick costs about 4.6 ms with the town, 50 machines and 200 zombies, so the rules use under a tenth of the 50 ms a 20-ticks-per-second sim can spend. Almost all of it is listening: each zombie asks `loudest_heard` every half second, and each ask checks every machine and walks the 2 m grid between them counting walls, so that cost grows with zombies x machines (about 0.34 microseconds per zombie-machine pair per tick; the 20 listens per tick make `horde.tick` 3.8 ms of the 4.6). The town adds only about 0.4 ms a tick (9%), because the wall walk pays for every grid cell it crosses whether or not a wall stands there, plus about 0.3 ms in `defense.tick`. The other big cost is the Director's `gain_now`: about 10 ms, once a second, all in one tick (50 machines x 8 directions x a 50 m wall walk), which is where the 20-23 ms worst ticks come from. Rough limits from these numbers: with 50 machines the average stays under 50 ms up to roughly 1,000-2,800 zombies (depending on how many sounds each one can hear), and with 200 zombies up to roughly 600 machines; but `gain_now`'s once-a-second spike alone would pass 50 ms at about 230 machines, so a big factory hits a once-a-second hitch before the average is in trouble. Memory is not a concern: the town plus 200 zombies is about 1.4 MB.

Suggestion (not done): cache each machine's outdoor level in `gain_now` and only recompute it when a piece is added, removed, opened or broken, since machines don't move; that removes the 10 ms spike.
